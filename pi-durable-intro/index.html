权衡 · zh-CN

崩掉也不丢活：pi-durable 是什么、为什么做、我们怎么选

跟着一次任务在三种架构（pi 正式版 / dsh / pi durable）里的旅程，看清“写日记”和“记账本”的差别，以及我们为什么选 durable 做底座。

事实阶梯

先说人话，再把事实讲到底。

正式版像“边跑边写日记”：活干完才记一笔，进程死了，正在写的这页就没了。dsh 像“日记写得全、还允许多人来看”，但正在写的这页照样会丢。durable 像“账本就是执行计划”：每做一步先记账，账本写到哪，活就干到哪——换个记账员（进程）也能接着干。

正式版把执行循环放在进程内存（runAgentLoop），消息完成后 append JSONL；durable 把执行拆成持久化任务（generation/tool），每步先原子提交（流式 ≤100ms 一批）再展示，崩溃后 harness.resume() 从 checkpoint 续推，工具调用得 interrupted 结果或按语义重放；dsh 是长驻宿主 + 可回放会话日志 + 多端附着，执行本身仍驻内存。

durable API 仍标 Experimental（v1.0→v1.1 均含 breaking changes）；100ms 提交节流的流式观感未经人工验证；对照基于 pi v1.1.0 快照与本会话 5 份调研（均带 file:line），dsh 部分基于其架构文档与 dsh-tui-pi 实测经验，实现细节可能随上游演进变化。

决策框架

共同目标: 用户提交一句话，模型思考、调用工具、给出答复——这条旅程不该半路蒸发。

pi 正式版（内存循环）

循环活在进程内存里，消息完成后才写日志。简单成熟，但进程一死，正在跑的这轮蒸发。

  • 崩溃时进行中的工作弱匹配

    整轮蒸发，只保住已完成消息

  • 长任务/多端的天花板弱匹配

    循环与单进程、单界面绑死

  • 实现与维护成本强匹配

    简单成熟，无额外存储成本

dsh（服务宿主）

agent 跑在长驻宿主服务里，命令与事件落会话日志、多端可附着；但进行中的一轮仍驻内存。

  • 崩溃时进行中的工作部分匹配

    历史与队列保住，进行中一轮丢

  • 长任务/多端的天花板部分匹配

    多端附着现成，执行本身不持久

  • 实现与维护成本部分匹配

    插件生态强，但宿主复杂度高

pi durable（账本执行）

执行拆成持久化任务：每步先原子提交再展示。进程死了，换个进程从断点接着跑。

  • 崩溃时进行中的工作强匹配

    断点续跑，中断工具可恢复

  • 长任务/多端的天花板强匹配

    存储即真相，天然支持续命/多端

  • 实现与维护成本部分匹配

    API Experimental，热路径有存储成本

决策规则: 短任务、单进程寿命内完成的活，选 A（成熟、简单）；需要多端附着与长驻服务，选 B；turn 越长、越怕丢、越要跨进程续命（崩溃/升级/子 agent），选 C。我们的组合：C 做执行底座 + A 的界面原样复用，自研收缩到最小宿主接口层。

术语表

值得记住的词

一轮（turn / run）
一次模型响应及其工具调用叫一个 turn；从用户输入到最终答复叫一轮 run。
agent loop
流式调模型 → 执行工具 → 再调模型的循环体，agent 的心脏。
工具调用
模型驱动的动作：跑 bash、读写文件、搜索代码。
checkpoint（断点）
任务每一步的存档，崩溃后从最近断点继续。
原子提交
一批变更要么全部落盘、要么全部不落；先记账再展示。
会话日志
按时间记录命令与事件的账目，可回放、可审计（dsh 的形态）。
宿主进程
长驻运行、承载 agent 服务的进程；UI 只是附着者。
extension（插件）
挂进 agent 的功能包；“可摘除”指官方原生实现后直接卸载自己的版本。

复述检验

现在能用自己的话讲清楚吗？

旧架构不是挺好吗，为什么要做 durable？

对短交互它确实够用。durable 解决的是“工作要活得比进程久”的场景：长 turn、崩溃或升级中断、多端、子 agent。这些在旧架构里是原理性限制，不是打补丁能解决的——就像日记本不可能替你把没写完的那页补出来。

崩溃之后 durable 恢复的到底是什么？

是工作本身，不只是历史。中断的工具调用拿到 interrupted 结果或按语义重跑，这一轮接着走完，排队的输入也还在。正式版和 dsh 都只能恢复已完成的记录。

我们要自己写多少？上游跑得快会不会白干？

实测核心胶水约 590 行；自研收缩到宿主接口层，其余复用正式版或做成可摘除 extension。上游 1-2 天一版，我们的对策是跟 release tag 合并、只加文件不改上游、避开上游自己的 TODO 清单，把白干风险压到最低；代价是 durable API 仍 Experimental。
